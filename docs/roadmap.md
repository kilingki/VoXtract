# 구현 로드맵

MVP는 단일 사용자가 파일 하나를 업로드하고 순차 ASR→FA 결과와 단어 시간을 확인·다운로드하는 흐름이다. 이 문서가 후속 기능 구현 허가를 뜻하지 않는다.

| 단계 | 범위 | 완료 조건 |
| --- | --- | --- |
| 0. 초기화 (현재) | 실행 골격, 안내 화면, 규칙·설계 | 로컬 실행·상태 API·정적 파일·스모크 검사 통과, 추론 의존 없음 |
| 1. 계약·정책 확인 | InferSwap/런타임 API, 오디오·텍스트 계약, 저장 정책 | 실제 명세의 출처·버전·예제 기록. 미확인 계약 분리. 지원 형식·제한·보존·재시도·최소 내보내기 형식 합의 |
| 2. 업로드·작업 저장 | 검증, 원자적 접수, 파일 큐·상태 조회, 최소 업로드 UI | 유효 파일만 접수. 중단·과대 파일·경로 조작·디스크 부족 처리. 재시작 후 대기 작업 보존 |
| 3. 순차 추론 | 확인된 API 어댑터, 단일 실행기, 실패·재시도·복구 | 계약 기반 순서 검증, 사용자 승인된 실제 샘플 E2E 성공. 단계 실패·중단·타임아웃·중복 서버·재시도 안전성 검증 |
| 4. 결과·내보내기 | 전사·단어 시간 모바일 화면, 합의한 형식 다운로드 | 갤럭시에서 결과·다운로드 확인. FA 실패를 완료로 표시하지 않음. 실제 녹음으로 전사·정렬 품질 검토 |
| 5. 외부 스마트폰 접근 | Tailscale·HTTPS, 필요한 PWA 설치 요소 | 집 밖 개인 스마트폰의 연결·업로드·조회·다운로드, 재접속·설치 후 동작 확인 |

기능 MVP는 1~4단계다. 집 밖 스마트폰 사용 목표는 5단계 검증까지 필요하다. 2~4단계에서 원본·중간 결과·결과의 삭제와 용량 관리도 완성한다.

후순위: 다중 사용자·인증 체계, DB, 병렬 추론·분산 큐, 실시간 녹음, 전사 편집·화자 분리, 오프라인 업로드, 고급 검색, 추가 내보내기 형식. 별도 요구와 근거 없이 도입하지 않는다.

첫 작업은 1단계 API 계약 확인이다. 기존 서비스 설정 변경이나 GPU 추론 없는 읽기 조사부터 시작한다.
