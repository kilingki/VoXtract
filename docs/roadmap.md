# 구현 로드맵

초기 MVP는 단일 사용자가 갤럭시 녹음 파일 하나를 업로드하고 Qwen ASR→Qwen FA 결과와 단어 시간을 확인·다운로드하는 흐름이다. 이 문서가 후속 기능 구현 허가를 뜻하지 않는다.

| 단계 | 범위 | 완료 조건 |
| --- | --- | --- |
| 0. 초기화 | 실행 골격, 안내 화면, 규칙·설계 | 로컬 실행·상태 API·정적 파일·스모크 검사 통과, 추론 의존 없음 |
| 1. 계약·정책 확인 | InferSwap/런타임 API, 오디오·텍스트 계약, 저장 정책 | 실제 명세의 출처·버전·예제 기록. 미확인 계약 분리. 지원 형식·제한·보존·재시도·최소 내보내기 형식 합의 |
| 2. 업로드·작업 저장 | 검증, 원자적 접수, 파일 큐·상태 조회, 최소 업로드 UI | 유효 파일만 접수. 큰 파일의 스트리밍·2시간 초과·중단·경로 조작·디스크 부족 처리. 파일 바이트·저장 총량 상한 없음. 재시작 후 대기 작업 보존 |
| 3. 순차 추론 | 확인된 API 어댑터, 단일 실행기, 실패·재시도·복구 | 계약 기반 순서 검증, 사용자 승인된 실제 샘플 E2E 성공. 단계 실패·중단·타임아웃·중복 서버·재시도 안전성 검증 |
| 4. 결과·내보내기 | 모바일 읽기 화면 → 단일 HTML 다운로드 → TXT·JSON 내보내기 | 실제 갤럭시 녹음으로 읽기·검색·재생 동기 확인. HTML을 서버 연결 없이 열어 읽기 구조 확인. FA 실패를 완료로 표시하지 않음 |
| 5. 외부 스마트폰 접근 | Tailscale·HTTPS, 필요한 PWA 설치 요소 | 집 밖에서 연결·업로드·다운로드 확인. 설치된 PWA에서 4단계 결과 화면과 재접속 동작 확인 |
| 확장 A. 미디어 파일 | 다른 오디오·MP4 등 동영상, 공통 오디오 준비 | 지원 형식·트랙·제한 확정. 추출 후 기존 ASR→FA 재사용. 무음·미지원 코덱·중단 처리와 원본 시간축 검증 |
| 확장 B. YouTube 링크 | 링크 검증·취득 후 공통 준비 경로 사용 | 허용 링크·도구·제한 확정. 내부 주소 접근 제한, 실패·중단·임시 파일 정리 검증. 파일 입력과 같은 결과 흐름 확인 |
| 확장 C. ASR 선택 | 두 번째 ASR 어댑터, 작업별 선택·설정 기록 | 실제 계약 확인 후 ASR 2개로 전사·FA 호환성 검증. 선택 고정·재시도·기존 결과 분리 확인 |

기능 MVP는 1~4단계다. 확장 A~C는 MVP 이후 범위이며 C는 입력 확장과 독립적으로 진행할 수 있다. 집 밖 스마트폰 사용 목표는 5단계 검증까지 필요하다. 2~4단계에서 원본·중간 결과·결과의 삭제와 용량 관리도 완성한다.

확장 단계는 설계 방향이며 현재 구현하지 않는다. 1~3단계부터 Qwen 응답이나 갤럭시 출처를 작업 조정·결과 형식에 직접 결합하지 않는다.

후순위: 다중 사용자·인증 체계, DB, 병렬 추론·분산 큐, 실시간 녹음, 전사 편집·화자 분리, 오프라인 업로드, 고급 검색, PDF 등 추가 내보내기 형식. 별도 요구와 근거 없이 도입하지 않는다.

## 1단계 진행 상태

2026-11-21: **1단계 완료 — 소스·설정 계약 조사와 2단계 선행 정책 확정**. 미검증 운영 계약은 분리해 기록했다.

- 근거·버전·실제 요청/응답 형태·오류·취소 의미·미검증 항목: [연동 계약 기록](integration-contracts.md).
- 확인한 계약을 반영한 준비·ASR·FA 경계와 재시작 시 보류 설계: [아키텍처](architecture.md).
- 지원 형식·길이·보존·삭제·디스크 여유·재시도·내보내기 채택 정책: [결정 기록](decisions.md#1단계-조사-결과와-정책-결정).
- 사용자 피드백 반영: 입력 길이 상한 2시간, 원본 파일 바이트·앱 저장 총용량 상한 없음, 디스크 여유 1 GiB 확보. 나머지 초기 정책도 채택했다. 30분 threshold는 3단계 검증 후보이며 잡음 제거는 기본 결과 평가 후 검토한다. 분할 경계·시간 복원·구간별 복구는 아직 구현·실제 추론 검증하지 않았다.
- InferSwap 상태 GET과 ASR·FA control/status GET은 각 3초 제한에서 시간 초과. ASR·FA 컨테이너는 중지 상태였으며 시작하지 않았다. 실제 서비스 버전·추론·갤럭시 품질은 미검증이다.
- 검증: WSL Ubuntu / Python 3.12.3에서 `uv run --locked python -m unittest discover -s tests -v`의 HTTP 스모크 검사 3개 통과, `uv run --locked python -m compileall -q backend tests` 통과. 비로그인 WSL PATH에서 uv를 찾지 못한 최초 실행 뒤 `/home/kjh/.local/bin/uv`로 재실행했다. 외부 저장소 테스트·GPU 추론은 실행하지 않았다.
- 문서 검증: 로컬 링크 16개·JSON 예제 2개 검사와 `git diff --check` 통과. 근거 소스와 문서의 요청 필드·sample 범위·시간 기준·실패 의미를 대조했다.

## 2단계 진행 상태

**2026-11-21 · 업로드·작업 저장 구현 완료**. 로컬 브라우저에서 녹음을 업로드하고 대기 작업을 조회·삭제할 수 있다. 저장·복구와 API 구조는 [아키텍처](architecture.md#2단계-업로드와-대기-큐)에 기록했다.

- WSL Ubuntu / Python 3.12.3 / FFmpeg 6.1.1에서 생성 WAV·M4A와 실제 HTTP 서버로 자동 검사 9개를 통과했다. WAV·M4A의 2시간 경계와 200 MiB 초과 WAV 접수, 잘못된 형식·손상·경로 조작, 전송 단절, 디스크 여유·ENOSPC 주입, 재시작과 대기 순서 보존, 이중 인스턴스 잠금, 삭제, 데이터 비공개를 확인했다.
- Windows Chrome 모바일 에뮬레이션에서 파일 선택, 업로드, 대기 목록 표시, 삭제 확인창과 삭제 후 목록 갱신을 검증했다.
- 실제 갤럭시에서 같은 내부망을 통해 M4A(AAC) 녹음 한 건을 브라우저로 직접 업로드해 접수·원본 저장·대기 상태를 확인했다. 트랙 재생 길이와 디코딩한 샘플 길이의 차이로 거절됐던 사례를 수정하고 회귀 검사를 추가했다. 자동 검사 10개가 통과했다.
- 집 밖 스마트폰 연결은 5단계 범위다.

## 3단계 진행 상태

**2026-11-21 · 순차 추론 구현, 모의 연동 검사, 실제 갤럭시 M4A 한 건 E2E 완료.** 작업 목록에서 기존 M4A를 선택해 실행할 수 있다. 결과 본문과 다운로드 화면은 4단계 범위다. [실행 방법](../README.md#저장된-녹음-전사)

- WSL Ubuntu / Python 3.12.3 / FFmpeg 6.1.1에서 자동 검사 23개가 통과했다. 계약 기반 모의 API로 기존 M4A, 동일 WAV와 ASR payload 전달, 분할 순서·시간축, FA 실패 뒤 재사용, 응답 불명 보류·재시작, 중복 실행 방지, 결과 저장 오류를 확인했다.
- Chrome 모바일 에뮬레이션에서 합성 M4A를 선택해 **전사 시작**을 누르고 **처리 완료**까지 확인했다.
- 기존 InferSwap 설정과 ASR·FA 컨테이너로 사용자 승인 녹음 한 건을 처리했다. 두 구간 모두 ASR→FA 응답을 저장했고, 원본·WAV·응답 해시 일치와 최종 정렬 시간 범위를 확인했다.
- 원본 재생과 단어 시간의 동기, 분할 경계의 전사·정렬 품질, 2시간 입력의 처리 성능, 불명 상태에서 실제 런타임 종료를 판별하는 절차는 추가 검증이 필요하다. 분할 기본값 30분은 검증 후보로 유지한다. [복구와 분할 방식](architecture.md#3단계-순차-실행)

## 4단계 구현 순서

1. **모바일 읽기 화면.** 완료된 전사를 시간 표시가 붙은 짧은 구간으로 나눠 보여 주고 본문 검색을 제공한다. 시간 표시를 누르면 해당 위치로 이동하고, 재생 중인 구간은 본문에서 강조한다. 3단계에서 처리한 실제 갤럭시 녹음으로 휴대폰의 읽기 편의성과 원본 재생 싱크를 먼저 검증한다.
2. **HTML 다운로드.** 앱과 같은 구간 구분, 문단, 시간 표시, 강조 구조를 단일 HTML 파일에 저장한다. 스타일을 포함하고 서버 연결 없이 갤럭시 브라우저에서 읽을 수 있는지 확인한다. 다운로드 파일의 오디오 재생과 동기 강조는 오디오 배포 방식을 확정한 뒤 다룬다.
3. **TXT·JSON 내보내기.** UTF-8 TXT와 버전 있는 내부 결과 JSON을 제공한다. 인쇄하거나 고정된 페이지로 공유할 필요가 생기면 브라우저 인쇄용 스타일과 PDF 저장을 검토한다. [내보내기 정책](decisions.md#확정-초기-입력저장내보내기)

## 작업을 요청하는 단위

기본적으로 위 표의 한 단계를 하나의 작업으로 요청한다. 각 작업은 조사·설계 보완·구현·검사·오류 수정·관련 문서 갱신까지 포함한다. 파일 수정이나 테스트 실행마다 요청을 나눌 필요는 없다. 다음 단계는 별도 요청이 있거나 처음부터 명시적으로 포함된 경우에만 진행한다.

| 요청 단위 | 선행 조건 | 작업 종료 시 확인할 결과 |
| --- | --- | --- |
| 1단계 계약·정책 확인 | 현재 골격과 실제 외부 문서·코드에 대한 읽기 접근 | 계약의 출처·버전·확인 근거, 미확인 항목, 정책 추천안과 사용자 결정 사항. 구현 가능한 항목과 막힌 항목 구분 |
| 2단계 업로드·작업 저장 | 관련 API·오디오 계약 및 지원 형식·제한·보존·삭제·용량 정책 확정 | 업로드 화면부터 저장·상태 조회·재시작 복구까지 동작하고 단계별 완료 조건 검사 |
| 3단계 ASR→FA 연동 | 필요한 실제 API 계약 확인, 2단계 완료 | 단일 실행·실패·중단·재시도·중복 방지 검사. 실제 추론은 별도 허가된 범위에서 검증 |
| 4단계 결과·내보내기 | 3단계 결과 확보, 내부 결과와 시간 단위 확인 | 읽기 화면과 재생 동기를 실제 갤럭시에서 먼저 확인하고 HTML·TXT·JSON 다운로드를 검증. 삭제·용량 관리 확인 |
| 5단계 외부 스마트폰 접근 | 로컬 MVP 검증, 네트워크·서비스 설정 변경 범위에 대한 사용자 요청 | 외부 갤럭시에서 연결·업로드·조회·다운로드·재접속 및 설치 동작 확인 |
| 확장 A·B·C | 각 확장의 실제 계약과 정책 확인 | 확장별로 따로 구현·검증. C는 A·B와 독립적으로 요청 가능 |

1단계의 조사가 끝나도 사용자 정책 결정이 남으면 전체 단계를 완료로 표시하지 않는다. 필요한 결정은 근거와 추천안을 모아 제시한다. 결정에 의존하지 않는 작업은 계속하며, 미확인 계약이나 사용자가 확인해야 하는 실제 기기 동작을 추정으로 완료 처리하지 않는다. 확정한 정책은 decisions.md, 구조·복구 설계는 architecture.md에 기록하고 이 문서에는 진행 상태와 작업 경계만 유지한다.

## 커밋·푸시를 포함하는 요청

요청 예시: “로드맵 2단계를 구현하고 검증·문서 갱신 후 GitHub 커밋·푸시까지 진행해.”

이처럼 커밋·푸시가 명시된 작업은 다음 절차까지 포함하며, 범위가 명확하면 매번 재확인을 요청하지 않는다. 이 문서 자체는 현재 변경이나 미래 작업의 커밋·푸시 실행 지시가 아니다.

1. 시작 시 브랜치·추적 원격·기존 변경을 확인한다. 기존 변경은 보존하고 요청 범위에 해당하는 변경만 포함한다. 기존 변경을 함께 커밋할지는 내용과 요청에서 판단하며, 불분명한 기존 변경은 임의로 포함하지 않는다.
2. 해당 작업을 구현하고 AGENTS.md의 기본 검사와 변경에 필요한 검사를 실행한다. 실제 추론·모바일 확인 등 실행하지 못한 검증과 남은 결정은 문서와 완료 보고에 명시한다.
3. 커밋 전 diff·스테이징 내용을 검토하고 `git diff --check`를 실행한다. 녹음·전사 본문·개인 데이터·비밀값이 포함되지 않았는지 확인한다. 문서만 바뀐 경우 검사는 변경에 비례해 수행하고 생략 이유를 보고한다.
4. 검증한 범위를 검토 가능한 커밋으로 묶고, 확인된 원격·브랜치로 일반 push한다. 강제 push나 기존 커밋 재작성은 별도 요청 없이 하지 않는다. 푸시 거절이나 권한 문제는 원인을 확인하고 기존 이력을 보존한다.
5. 완료 보고에 변경 요약, 검사 결과, 남은 결정·미검증 항목, 커밋 해시, 푸시 대상과 성공 여부를 남긴다. 커밋·푸시 성공과 기능 단계의 완료 여부를 구분한다.

의존 관계가 분명해지고 정책이 확정된 뒤에는 여러 단계를 한 요청으로 묶을 수 있다. 이때도 단계별 검사와 완료 상태를 기록하고, 실제 추론·서비스 설정 변경은 요청에서 허용한 범위만 실행한다.
